# RFC-0031 — Narcissistic Supply Substitution Therapy (NSST)

## Abstract

This document specifies the Narcissistic Supply Substitution Therapy (NSST),
an organizational intervention protocol designed to decouple leadership
narcissistic supply needs from mandatory presence policies. NSST provides
structured substitution mechanisms for the six supply channels attenuated
by remote work (physical presence, dominant body language, immediate attention,
subordinate observability, visible status signals, authority demonstrations),
reducing the Mandatory Presence Correlation Coefficient (MPCC, RFC-0028).
The NSST Efficacy Metric (NSEM) quantifies substitution success. A three-level
implementation gradient enables proportional deployment.

> **Satire Notice**: This document is published in the **Humor** stream.
> While technically coherent, its primary purpose is satirical illumination
> of organizational dynamics. The OSC does not recommend deploying NSST
> without informed consent, a qualified organizational epistemologist,
> and a very large mirror.

## 1. Introduction

The Mandatory Presence Enforcement Protocol (RFC-0028) establishes a robust
correlation (MPCC = 0.73, p < 0.001) between leadership narcissism and
mandatory physical presence mandates. Paper-012 §2.3 demonstrates the mechanism:
remote work attenuates six specific narcissistic supply channels, creating
supply disruption that leaders compensate for through proximity enforcement.

NSST addresses the root cause rather than the symptom. Instead of suppressing
remote autonomy (RFC-0028 ASM), NSST provides epistemically benign substitutes
for each attenuated supply channel. The conservation principle (Theorem-007)
dictates: supply cannot be eliminated, only redirected. NSST engineers the
redirection.

## 2. Terminology

| Term | Definition |
|------|------------|
| **Supply Channel** | Mechanism for narcissistic supply extraction (admiration, compliance, attention, status) |
| **Attenuation Factor (α)** | Remote supply extraction efficiency reduction (0 ≤ α ≤ 1); α = 1 = complete attenuation |
| **Substitution Mechanism** | Organizational practice providing equivalent supply via alternative channel without mandated presence |
| **NSST Efficacy Metric (NSEM)** | NSEM = 1 - (MPCC_post / MPCC_pre); positive = successful decoupling |
| **NSST Gradient** | Three-level intensity: L1 Nudges, L2 Structured Substitutes, L3 Coaching Referral |
| **Supply Disruption Event (SDE)** | Remote work adoption interrupting narcissistic supply (per RFC-0028) |
| **Visual Dominance Need (VDN)** | Leader's requirement for physical subordinate visibility (per RFC-0028) |
| **Mirror-Gazing Index (MGI)** | Leader time in visibility-seeking vs. value-adding work (per RFC-0028) |

## 3. Supply Channel Substitution Specification

### 3.1 Supply Channel Taxonomy (per Paper-012 Table 1)

| Channel ID | Supply Mechanism | Remote Attenuation | Primary Substitution Target |
|------------|------------------|-------------------|----------------------------|
| SC-01 | Constant physical presence | High | Virtual Presence Acknowledgment (VPA) |
| SC-02 | Dominant body language | High | Structured Turn-Taking Protocol (STTP) |
| SC-03 | Immediate attention | High | Async Attention Routing (AAR) |
| SC-04 | Subordinate observability | High | Transparent Work Streaming (TWS) |
| SC-05 | Visible status signals | Complete | Digital Status Artifacts (DSA) |
| SC-06 | Authority demonstrations | High | Decision Log Transparency (DLT) |

### 3.2 Substitution Mechanisms (Normative)

#### SC-01: Virtual Presence Acknowledgment (VPA)

**Requirement 1**: Organizations implementing NSST Level 2+ **MUST** deploy VPA as a
continuous, low-friction presence signaling mechanism.

**Mechanism**: Subordinates opt-in to lightweight presence indicators
(status emoji, focus-time blocks, availability windows) visible to leadership
via dashboard. Unlike surveillance (RFC-0028 ASM), VPA is **pull-based** —
leaders observe aggregate patterns, not individual tracking.

**Protocol**:
```
VPA Cycle (per RFC-0017 CBP rhythm):
1. Subordinate sets availability window (e.g., "Deep work 09:00-11:00")
2. System aggregates → Leadership Presence Dashboard (LPD)
3. Leader observes aggregate presence density
4. Supply satisfaction: Leader sees "team is here" without mandating location
```

**Supply Equivalence**: VPA satisfies the *existence confirmation* component
of physical presence without *location enforcement*.

#### SC-02: Structured Turn-Taking Protocol (STTP)

**Requirement 2**: Organizations **MUST** replace ad-hoc meeting dominance
with STTP in all synchronous forums exceeding 4 participants.

**Mechanism**: Rotational speaking order with time-boxed slots, enforced by
meeting facilitator (human or RFC-0014 DTS-compliant bot). Eliminates body
language dominance; substitutes with *procedural dominance* — the supply of
controlling the floor.

**Parameters**:
- Slot duration: 3 minutes (configurable)
- Rotation: Round-robin by tenure (newest first — RFC-0025 SEP alignment)
- Override: "Point of Order" (30s) for urgent interjections

**Supply Equivalence**: STTP satisfies *dominance display* through fair
procedure — narcissistic leaders can still "run the meeting" by designing
the rotation rules.

#### SC-03: Async Attention Routing (AAR)

**Requirement 3**: Organizations **SHOULD** implement AAR for leader-subordinate
attention requests, replacing synchronous interruption.

**Mechanism**: Structured attention request queue with SLA tiers:
- Tier 1 (Critical): 15-min response SLA, escalates to synchronous
- Tier 2 (Standard): 4-hour response SLA, async resolution
- Tier 3 (Context): 24-hour SLA, batched digest

**Protocol**:
```
AAR Request Flow:
1. Subordinate submits request via AAR interface
   (Slack/Teams/email tag)
2. System classifies tier (ML-assisted + subordinate self-tag)
3. Leader dashboard shows queued requests with SLA countdown
4. Leader processes in batches -> supply of "being needed"
   satisfied asynchronously
```

**Supply Equivalence**: AAR satisfies *immediate attention demand* through
structured urgency signaling, not synchronous interruption.

#### SC-04: Transparent Work Streaming (TWS)

**Requirement 4**: Organizations **MAY** deploy TWS for leaders with
MGI > 0.6 (RFC-0028 threshold).

**Mechanism**: Voluntary, time-boxed work streaming (screen share, narrated
coding, design walkthrough) — subordinate-driven, leader-observed. Inverts
RFC-0028 surveillance: subordinates *offer* observability; leaders *consume*
supply.

**Privacy**: Extends RFC-0022 §3.8 privacy model:
- Opt-in only (no default streaming)
- Visibility levels: Team / Leadership / Public
- 30-day auto-delete of recordings
- No performance evaluation linkage

**Supply Equivalence**: TWS satisfies *observability need* through
curated transparency — leaders see work happening without mandating presence.

#### SC-05: Digital Status Artifacts (DSA)

**Requirement 5**: Organizations **MUST** provide DSA as status-signal
substitutes for physical artifacts (corner office, reserved parking,
executive floor).

**Mechanism**: Verifiable digital credentials displayed on internal profiles:
- "Architect of [System]" badge (technical authority)
- "Decision Owner: [Domain]" badge (formal authority)
- "Mentor: [Count] mentees" badge (social authority)
- "CBP Hub: [Frequency]" badge (network centrality — RFC-0017)

**Supply Equivalence**: DSA satisfies *visible status signaling* through
earned, verifiable digital artifacts — supply shifts from *positional* to
*meritocratic* status.

#### SC-06: Decision Log Transparency (DLT)

**Requirement 6**: Organizations **SHOULD** implement DLT for all decisions
affecting > 3 people or > $10k budget.

**Mechanism**: Structured decision logs (per RFC-0014 DTS) with:
- Decision statement
- Alternatives considered
- Evidence cited
- Authority exercised (explicit)
- Dissent recorded (RFC-0010 EIRP)
- Outcome tracking

**Supply Equivalence**: DLT satisfies *authority demonstration* through
documented decision quality — leaders display competence, not merely control.

## 4. NSST State Machine

```ascii
NSST Intervention Cycle:

ASSESSMENT
  |
  v
MPCC Measurement (RFC-0028 §3.1)
  |
  v
Channel Attenuation Profile (Paper-012 Table 1)
  |
  v
CHANNEL SELECTION
  |
  v
Select channels with α > 0.5 (high attenuation)
  |
  v
SUBSTITUTION DEPLOYMENT
  |
  v
Deploy substitution mechanisms per §3.2
  |
  v
NSEM MONITORING
  |
  v
Measure MPCC at 30-day intervals
  |
  v
NSEM = 1 - (MPCC_t / MPCC_0)
  |
  v
GRADIENT ESCALATION (if NSEM < threshold)
  |
  v
Level 1 → Level 2 → Level 3
```

**State Transitions**:
- ASSESSMENT → CHANNEL_SELECTION: MPCC > 0.5 triggers NSST
- CHANNEL_SELECTION → SUBSTITUTION_DEPLOYMENT: Always
- SUBSTITUTION_DEPLOYMENT → NSEM_MONITORING: 7-day stabilization period
- NSEM_MONITORING → GRADIENT_ESCALATION: NSEM < 0.3 at 30-day mark
- GRADIENT_ESCALATION → SUBSTITUTION_DEPLOYMENT: Add next level mechanisms

## 5. NSST Efficacy Metric (NSEM)

### 5.1 Definition

```
NSEM = 1 - (MPCC_post / MPCC_pre)

Where:
- MPCC_pre = MPCC at NSST initiation (RFC-0028 §3.1)
- MPCC_post = MPCC at measurement interval (30/60/90 days)
```

### 5.2 Interpretation

| NSEM Range | Interpretation | Action |
|------------|----------------|--------|
| NSEM ≥ 0.5 | Strong substitution | Maintain current gradient level |
| 0.3 ≤ NSEM < 0.5 | Moderate substitution | Escalate one gradient level |
| 0.0 ≤ NSEM < 0.3 | Weak substitution | Escalate two levels; review channel selection |
| NSEM < 0.0 | Substitution backfired (MPCC increased) | Halt; root-cause analysis; consider Level 3 |

### 5.3 Calibration

Baseline MPCC from RFC-0028 multi-org study: 0.73.
Target: NSEM ≥ 0.4 → MPCC_post ≤ 0.44 (substantial decoupling).

## 6. Three-Level Implementation Gradient

| Level | Name | Mechanisms | Trigger | Cost | Reversibility |
|-------|------|------------|---------|------|---------------|
| 1 | **Nudges** | VPA (opt-in), DSA (badges), AAR Tier 3 | MPCC > 0.5 | Low (config only) | Effortless (disable) |
| 2 | **Structured Substitutes** | STTP (mandatory), AAR Tier 1-2, TWS (opt-in), DLT | MPCC > 0.6 ∨ NSEM < 0.3 at L1 | Medium (process change) | Moderate (retire protocols) |
| 3 | **Supply Architecture Redesign** | c₁-c₆ channel redesign, NSST/PTDP/NEDP integration, Board-level G(O) accountability dashboard | MPCC > 0.7 ∨ NSEM < 0 at L2 | High (structural) | Moderate (policy rollback) |

**Escalation Rules**:
- L1 → L2: Automatic if NSEM < 0.3 at Day 30
- L2 → L3: Automatic if NSEM < 0.0 at Day 60 OR MPCC > 0.7
- L3 → L2: If NSEM ≥ 0.5 sustained 90 days
- L2 → L1: If NSEM ≥ 0.5 sustained 60 days

- L2 → L1: If NSEM ≥ 0.5 sustained 60 days

## 7. Supply Architecture Redesign (Level 3 Methodology)

### 7.1 Purpose

Level 3 "Supply Architecture Redesign" is the highest NSST gradient. It is
triggered when NSEM < 0.0 at Level 2 (Day 60) or MPCC > 0.7, indicating
that substitution mechanisms have failed to decouple leadership narcissistic
supply from mandatory presence mandates. Level 3 is not individual therapy
— it is a Board-authorized organizational redesign of the supply channel
architecture.

### 7.2 Design Principles

| Principle | Description |
|-----------|-------------|
| **Organizational, not individual** | Redesigns supply *channels* (c₁-c₆), not the leader's psychology |
| **Theorem-007 Compliant** | Respects supply conservation (Theorem-007): ΣΔ_j = \|S\|₁ - \|S'\|₁ |
| **G(O)-Accountable** | Board-level G(O) dashboard with quarterly review |
| **Reversible** | Structural changes must be reversible within 2 quarters |
| **Supply-Aware** | Distinguishes narcissistic channels (c₂, c₅, c₆) from operational (c₃, c₄) |

### 7.3 Supply Architecture Redesign Methodology

The redesign proceeds in four phases:

| Phase | Duration | Activities | Deliverable |
|-------|----------|------------|-------------|
| **1. Supply Audit** | 2 weeks | Map current S_i/‖S‖₁; measure α_i; compute P_i = ρ(N) - S_i | Supply Channel Map + Pressure Profile |
| **2. Redistribution Design** | 3 weeks | Engineer Δ_j for each channel; prioritize operational channels (c₃, c₄); design c₇ mutation safeguards | Supply Architecture Redesign Spec |
| **3. Board Authorization** | 1 week | Present G(O) reduction target; G(O) accountability dashboard spec; rollback plan | Board Authorization Record |
| **4. Phased Deployment** | 8 weeks | Week 1-2: c₅, c₆ (status, authority); Week 3-4: c₂, c₆ (body language, authority); Week 5-6: c₃, c₄ (attention, observability); Week 7-8: c₁ (physical presence) | Deployment Report + G(O) Baseline |

### 7.4 Redistribution Patterns by Channel

| Channel | Current α_i | Redesign Target | Mechanism (Δ_j) |
|---------|-------------|-----------------|-----------------|
| c₁: Physical presence | 0.9 | → 0.3 (operational minimum) | Virtual Presence Acknowledgment (VPA) + outcome-based presence |
| c₂: Body language | 0.8 | → 0.2 | Structured Turn-Taking Protocol (STTP) — procedural dominance |
| c₃: Immediate attention | 0.8 | → 0.6 (operational) | Async Attention Routing (AAR) — SLA-tiered async |
| c₄: Observability | 0.9 | → 0.4 | Transparent Work Streaming (TWS) — opt-in, outcome-focused |
| c₅: Status signals | 1.0 | → 0.3 | Digital Status Artifacts (DSA) — earned badges, not positional |
| c₆: Authority demo | 0.7 | → 0.4 | Decision Log Transparency (DLT) — documented rationale |

**Supply Conservation Check**: Σ Δ_j = \|S\|₁ - \|S'\|₁ (Theorem-007 conservation law)

### 7.5 Governance & Accountability

| Role | Responsibility |
|------|----------------|
| **Board** | Quarterly G(O) review; authorize/deny Level 3; approve rollback |
| **CTO/People Ops** | Execute redesign; monitor G(O) dashboard; trigger rollback if G(O) ↑ |
| **RFC-0024 TIP** | Validate operational channel redesign (c₃, c₄) doesn't degrade trench intelligence |
| **RFC-0023 PGP** | Ensure no NSST data informs promotion/compensation (separation) |

### 7.5.1 G(O) Accountability Dashboard

Board receives quarterly:

| Metric | Target | Alert If |
|--------|--------|----------|
| G(O) = D_KL + ‖φ‖₁ | < 0.5 | > 0.7 for 2 consecutive quarters |
| NSEM | ≥ 0.5 | < 0.3 for 2 consecutive months |
| MPCC | < 0.4 | > 0.6 for 2 consecutive months |
| Channel redistribution | c₃, c₄ ≥ 40% of ‖S‖₁ | c₁, c₅, c₆ > 60% of ‖S‖₁ |

**Rollback Trigger**: Any metric in "Alert If" for 2 consecutive
quarters → automatic Level 3 rollback to Level 2 + independent audit.

## 8. Security and Privacy Considerations

NSST mechanisms that observe leader or subordinate behavior (VPA, TWS, AAR)
extend the RFC-0022 CCBP §3.8 privacy model:

- **Opt-in default**: No mechanism activates without explicit consent
- **Visibility levels**: Self / Team / Leadership / Organization
- **Data minimization**: Aggregate dashboards only; no individual tracking
- **Retention**: 30-day auto-delete for behavioral data; decision logs (DLT) permanent
- **No performance linkage**: NSST data **MUST NOT** inform performance reviews,
  compensation, or promotion decisions (RFC-0023 PGP separation)
- **Right to withdrawal**: Any participant may withdraw at any time; data purged in 24h
